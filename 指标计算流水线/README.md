# 基金经理行为指标计算流水线（离线版）

把**指标计算源码**与**原始数据**放在一起，按执行顺序整理成一套可以**手动逐步运行**、最终重建出「我们的指标数据」（主分析面板）的流水线。

全部计算只读取本目录 `data/` 下的本地 CSV，**不依赖 AKShare / 网络**，可在无网环境复现。

---

## 一、目录结构

```
指标计算流水线/
├── run_all.py                  # 一键顺序执行 00 → 99
├── lib_metrics.py              # 唯一计算库：13 个行为指标 + 4 控制变量的纯计算函数
├── 00_构建面板骨架.py          # 步骤 0：由基金净值历史_全量.csv 净值覆盖派生观测索引（基金-季度），彻底脱离元面板
├── 01_L1_背景特征.py           # 步骤 1：任职期限 / 基金年龄 / 控制变量
├── 02_L2_持仓偏离.py           # 步骤 2：主动份额 AS / 行业偏离 ICI(+raw) / 行业集中度 HHI(+raw)
├── 03_L3_交易执行.py           # 步骤 3：风格漂移 SDI / 真·双边换手率 TO_two_sided / 过度交易 OCI_two_sided
├── 04_L4_风险应对.py           # 步骤 4：主动风险增益 ARG / 收益波动率
├── 05_L5_认知偏差.py           # 步骤 5：处置效应 de / 羊群 lsv / 风险不对称
├── 99_合并面板.py              # 步骤 99：把各层左拼成最终面板
├── data/                       # 全部输入数据（与源码同目录，离线自洽）
│   ├── L1_背景特征层/
│   ├── L2_持仓偏离层/
│   ├── L3_交易行为层/
│   ├── L4_风险应对层/
│   ├── 基金基础信息/
│   ├── 股价行情/
│   └── FF因子/                  # FF3(合并版, 季度) + FF5(月度→季度聚合)，离线自洽
└── output/                     # 各步骤产物 + 最终主分析面板_重建.csv（运行后生成）
```

## 三、怎么跑（完整复现指南）

> **核心约定**：本流水线只依赖 `指标计算流水线/data/` 下的本地 CSV，`run_all.py` 会顺序调用 00→99。

`data/股价行情/个股月收益率_全量.csv` 由下列脚本按持仓股全量重抓（约 4500+ 只，2016-01→2026-01）：

- 进度：`.done.txt`（已抓取）/ `.failed.txt`（无覆盖跳过）逐只累加；进程结束即完成。

### 步骤 2：运行流水线（两种方式，等价）

**方式 A — 一键顺序执行（推荐）：**

```bash

```

脚本按 00 → 01 → … → 99 依次 `subprocess` 调用每个步骤，任一步失败即中止并报错；打印每一步耗时。

**方式 B — 手动逐步执行（满足"按顺序依次手动执行源码"）：**

在「指标计算流水线」目录下，**严格按下面编号顺序**逐条运行：

```bash
"$PY" 00_构建面板骨架.py
"$PY" 01_L1_背景特征.py
"$PY" 02_L2_持仓偏离.py
"$PY" 03_L3_交易执行.py
"$PY" 04_L4_风险应对.py
"$PY" 05_L5_认知偏差.py
"$PY" 06_因变量.py
"$PY" 99_合并面板.py
```

> 也可以单独运行某一步（例如只重算 L2）：先确保 `output/00_面板骨架.csv` 已存在，
> 再跑 `"$PY" 02_L2_持仓偏离.py` 即可，产物覆盖 `output/L2_持仓偏离.csv`。

### 步骤 3：运行内部一致性诊断（验证自洽，非 vs 元面板）

```bash
"$PY" diagnostics/内部一致性诊断.py
```

- 校验：主键唯一、面板行数 == 骨架行数、`excess_return == quarter_return − rf`（100%）、
  `future_return == 同基金下一季度 quarter_return`（100%）、`ff3/ff4/ff5_adj_return` 基金内常数、
  双 NAV 算法 `quarter_return` 互验（Pearson）。
- 产物：`diagnostics/内部一致性报告.html`（分级报告）+ 控制台打印 `status: OK / 问题数`。

### 步骤 5：常见坑位

- **`ModuleNotFoundError: lib_metrics`**：必须在「指标计算流水线」目录下运行（脚本用 `sys.executable`
  自动定位同目录的 `lib_metrics.py`）；诊断脚本会自动把父目录加入 `sys.path`。
- **某指标整列为 NaN**：检查对应 `data/` 输入文件是否存在 / 编码是否为 `utf-8-sig`（见步骤 4 清单的文件路径）。
- **想换数据**：把同名 CSV 放进 `data/` 对应子目录覆盖即可，无需改代码（路径在 `lib_metrics.D()` 中集中管理）。
- **断点续传失效**：若 `.done.txt`/`.failed.txt` 残留导致重新抓取异常，删除这两个标记文件再跑抓取脚本即可全量重抓。

## 五、指标口径与计算说明（自算、不依赖元面板）

本流水线**不**读取任何模拟占位面板（原 `主分析面板_修正版.csv`=mvp_panel_v22 已于 2026-08-14 隔离删除），所有指标均由 `data/` 真实原始数据
在流水线内重新计算，目标是「离线、自洽、可复现」。下列为关键口径与工程说明：

1. **ARG / de / RG 覆盖依赖 `个股月收益率_全量.csv`**：该文件由 `代码/fetch_stock_monthly_returns_akshare.py`
   经 AkShare（新浪源）按持仓股全量重抓生成（约 4500+ 只，覆盖 2016-01→2026-01）。抓取完成后
   ARG 覆盖 99.9%、RG 88.8%、de 44.4%（de 仅 6/12 月快照故覆盖天然偏低）。
   **重抓为长任务（顺序抓取、约 0.9s/只、带断点续传 `*.done.txt`/`*.failed.txt`）**；若仓库已随附该 CSV
   （364100 行、约 4185 只抓取成功）则无需再抓。旧版仅含约 108 只，现已废弃。
2. **ICI / industry_hhi 已升级为股票级→申万31 聚合（2026-08-12）**：旧口径用 `基金行业配置_全量.csv`
   （82 混标，`SW31_MAP` 等权拆分 → 均值 0.053/0.014）**已废弃**。现用户经 AKShare 下载
   `stock_code→申万一级` 映射（`股票行业映射.csv`，5203 只，覆盖 99.2%），对
   `基金持仓明细_全量修正版.csv`（股票级 hold_ratio）**按股票聚到申万31** 重算，
   写入 `行业集中度HHI_申万31.csv`，由 `_load_hhi_merged()` 读取并入面板。
   **推荐口径取归一化版本（权重 Σ=1）**：`industry_hhi`(面板均值≈0.241) / `ICI`(≈0.124)；
   原始 NAV 权重并列保留为 `industry_hhi_raw`(≈0.169) / `ICI_raw`(≈0.108)。
   归一化 HHI 与原面板目标 0.2595 最接近（SW31 更细→略低，差距≈0.02 来自分类粒度，合理）；
   ICI 因 SW31 更细、行业偏离更大（0.124 vs 0.071，合理）。
   **AS_improved / SDI 不受影响**（分别用沪深300+中证500 基准权重、4 风格指数，与行业分类完全无关）。
3. **换手率自 2026-08-12 起已【统一为双边 TO_two_sided】（单边 TO_calc / OCI 已移除）**：
   项目原有一份被误归为"无用数据"的真实双边换手率文件 `数据/无用数据/基金换手率_计算值.csv`
   （含 `total_buy / total_sell / avg_aum`，且 `turnover_rate=(买+卖)/(2×净资产)` 已校验吻合），
   现拷入 `data/L3_交易行为层/基金换手率_双边_含卖出.csv`，其 `TO_two_sided`（真·双边换手率）
   为本层唯一主变量：**`TO_two_sided = (total_buy + total_sell) / (2 × avg_aum)`**。
   覆盖 **200 基金 / 2021H1–2025H1（半年频，9 个快照）/ 约骨架 18%（200/400 基金；因半年频，观测占比更低）**——待 CSMAR/Wind 确定性双边换手率补齐全部 400 只（见 `数据下载提示词_2026-08-13.md` P1）。
   - **单边口径为何被弃**：`基金持仓变动_批量.csv` 仅含「本期累计买入金额」一栏（无卖出列），
     只能算买入侧单边 `TO = 买入×1000 / 平均净资产`，系统性低估真实换手，故不再作为主变量。
   - **OCI 同步为双边**：`OCI_two_sided = (TO_two_sided − 基金内均值) / 基金内标准差`，与 TO_two_sided 一一对应。
   - **论文口径**：全部统一使用双边子集（TO_two_sided / OCI_two_sided），覆盖率 33.3%，缺失季度为 NaN。
4. **SDI 滚动窗口=8、风格指数取 399373/4/6/7 四个**：窗口由 12 缩短为 8（2026-08-12），
   暖机期从 12 季降到 8 季，SDI 首次可用提前到 2022Q3，有效跨度≈4.3 年、覆盖 66.6%。
   研究基金净值多始于 2020Q2 附近，无样本外历史可借，故用缩短窗口拉长时间跨度。
5. **de 仅 6/12 月全持仓快照**：遵循 Odean(1998) 快照法，季度末为 6/30、12/31 的快照才参与计算；
   合并后面板中其他季度的 de 为缺失（NaN），与原设计一致。
6. **risk_asym 已改为【逐期滚动时变量】（2026-08-12 修复）**：原实现按「基金全历史」取一个常量
   （同基金各季度取值相同）→ 在基金固定效应面板回归中变异为 0、无法识别。现改为
   `calc_risk_asym(window=8, min_periods=4)` 滚动窗口逐期（窗口内盈利期>0 收益标准差 − 亏损期≤0 收益标准差），
   覆盖 73.7%、同基金内取值数中位 21、均值 0.034、范围 [−0.126, 0.479]。
   文献依据：杠杆效应（leverage effect, Black 1976 / Christie 1982 / Bekaert & Wu 2000）。
7. **日期约定**：各原始文件日期为季度末/半年末（如 2020-03-31），面板 `report_date` = 季度末 **+1 天**
   （2020-04-01）。`lib_metrics.to_panel_date()` 统一把指标对齐到该约定，确保 99 步精确拼接。
8. **lsv（交易趋同度 / 共识偏离度，LSV 1992 口径）**：本仓库交易文件只有「累计买入股票明细」(买入侧)，
   无真实逐股买卖方向，故用**持仓快照增减方向**作买卖代理。注意：第 3 条新增的
   `基金换手率_双边_含卖出.csv` 虽含 fund 级 `total_buy/total_sell`，但那是**基金层面的买卖总额**，
   **不含每只股票的买卖方向**，因此 LSV 需用持仓快照增减方向代理（增持基金数 B / 减持 S）。
   **p_i 采用 LSV1992 教科书买入占比 `p_i = B/(B+S) ∈ [0,1]`**（2026-08-12 由带符号净比 (B−S)/(B+S) 改回，
   使代码/文稿/教科书三者一致并可恢复负向"反向交易"语义），`p̄_t` 为市场横截面均值，套用 LSV1992 二项式 AF。
   重建 lsv 均值≈0.089、范围 [−0.068, 0.276]、约 0.2% 为负，量级贴合经典 LSV 文献（Wermers≈0.02–0.07）、覆盖≈44%。
   原面板 lsv 均值≈−0.23（基于真实逐股买卖方向）**数据源不同，无法直接复现**；本列为可计算代理，已在论文中改称中性"交易趋同度"。
   若需严格复现原面板 lsv，需补充含**逐股买卖双向方向**的持仓变动明细数据源（P2，见《数据下载需求_待补源.md》）。
9. **因变量(绩效/风险)全部自算（2026-08-12 重构）**：`06_因变量.py` **全部从原始数据在流水线内自算**
   （不再导入论文原始面板）：
   - `quarter_return / future_return / excess_return / abs_return`：由 `基金净值历史_全量.csv` 日收益复利 / 取同基金下一季度 / 减 FF3 季度 rf / 取绝对值；
   - `RG`（收益差）：`quarter_return − Σ w_i·r_i`（持仓快照权重 × 个股季度收益，来源 `基金持仓明细_全量修正版.csv` + `个股月收益率_全量.csv`）；
   - `ff3/ff4/ff5_adj_return`：单基金时序回归 `excess_return ~ 因子` 的截距(alpha)；FF3/FF4 用
     `FF因子_合并完整版.csv`（季度，含 MKT_excess/SMB/HML/MOM/rf），FF5 用 `FF5月度因子.csv`（月度→季度聚合）。
   最终面板同时含「自变量(行为指标)+控制变量」与「因变量」，可直接用于回归。
10. **mgr_total_tenure_v2 口径（2026-08-12 修正）**：取 `report_date` 时刻**在任经理**
   （`start ≤ report_date ≤ end/至今`）的任职起始日，任期 = `report_date − 起始日`（单位天）。
   现口径即学术标准的「现任经理任期」，不可能为负；均值≈1479 天、覆盖 99.7%。
   （旧实现取「全期最早任职经理」致早期季度 tenure 为负，已废弃。）
11. **样本期修正（2026-08-13）**：① 骨架 `load_skeleton()` 新增「未来季度剔除」——仅保留
    `季度末 ≤ 净值数据最大日期(2026-08-07)` 的季度，自动剔除尚未结束、收益残缺的 2026Q3，
    样本由 27 季(2020Q2–2026Q3, 5397) 收紧为 **26 季(2020Q2–2026Q2)**（当时按 200 基金口径计 5197 观测）；口径统一后的计数见第 13 条。

## 七、常见问题

- **`ModuleNotFoundError: lib_metrics`**：必须在「指标计算流水线」目录下运行，或用 `PYTHONPATH=. python 00_构建面板骨架.py`。
- **某指标整列为 NaN**：检查对应 `data/` 输入文件是否存在/编码是否为 `utf-8-sig`；例如 ICI/行业映射缺失会触发第 2 条口径回退。
- **想换数据**：把同名 CSV 放进 `data/` 对应子目录覆盖即可，无需改代码（路径在 `lib_metrics.D()` 中集中管理）。
